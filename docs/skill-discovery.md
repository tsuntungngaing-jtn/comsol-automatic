# 安装到豆包的技能管理列表

目标是豆包客户端的技能管理列表。把文件复制到本地工作目录、让 Agent 读取 SKILL.md、连接 MCP 并成功求解，都不能代替这一步安装。

## 使用豆包的“上传技能”入口

本次检查的豆包客户端程序资源包含“我的技能”“新建”（部分默认文案为“创建”）及“上传技能”入口。进入技能管理页后，按当前界面选择 **新建／创建 → 上传技能 → 选择文件**，选择完整发布包 `Comsol-Automatic-v0.1.0.zip`。若界面层级不同，使用当前页面实际提供的“上传技能”入口，不凭空假设按钮位置。

本包 ZIP 包含根技能目录、SKILL.md 和完整 MCP 源码，不含真实 Token、虚拟环境、运行模型或日志。不要直接上传已运行过的本地安装目录，其中可能包含这些文件；优先使用经过审计的发布 ZIP。客户端支持单独 SKILL.md、ZIP 和文件夹，不代表本项目可以省去所需的 MCP 源码。

提交后等待界面的上传结果与安全检测状态，再在“我的技能”或管理列表搜索 `comsol-automatic` / `Comsol-Automatic`，确认条目已出现并可使用。客户端文案明确区分上传成功与安全检测完成；不能仅凭上传完成就报告技能已可用。若提示失败，保留具体错误，不通过删文件或改名猜测、规避检测。

已有 COMSOL MCP 连接器继续使用原服务，上传技能不要求更改 Header、Token 或端口。首次安装运行时与连接器的步骤见 [连接器指南](connectors.md)。

## Agent 该怎样完成这一步

先检查是否有可调用的豆包技能安装/导入工具，或能访问目标客户端的受支持操作能力。用户要求安装到豆包，不能擅自改成安装到其他 Agent 的目录。当前工具没有接入豆包管理页时，先准备并审计完整 ZIP，准确说明“安装包已准备，豆包列表安装尚未完成”，再请用户通过上述入口导入；不声称已经替用户完成注册。

仍遵守用户的无屏幕识别要求。不得为完成导入调用截图识别、OCR、模拟点击，或从本地数据库提取登录凭据。没有受支持的安装工具时，不构造未公开的原生桥或伪造客户端索引。

本机公开客户端资源 `static/js/async/8011.js` 提供“我的技能”“上传技能”“选择文件／文件夹”及安全检测状态文案；`static/js/39368.js` 还包含 `AGWManageCreateSkill`、`AGWManageListSkillsByUser` 管理流程，区别于本地技能扫描。本包没有修改或分发客户端代码。没有掌握受支持的上传参数、认证方式和接口契约时，不按这些函数名拼接请求。观察适用于本次检查的安装版本，其他版本按实际界面确认。

## 其他 Agent 的本地目录安装

`scripts/install_skill.py` 是本地文件安装器，适合 Codex 等明确从指定目录加载技能的客户端：

```powershell
python .\scripts\install_skill.py --skills-dir (Join-Path $env:USERPROFILE ".codex\skills")
```

它复制完整公开源码并拒绝覆盖已有目录；不安装 Python 依赖、不操作豆包技能管理服务，也不能使豆包列表自动注册。不要把这个命令当成豆包安装步骤。

## 分别验收

| 检查 | 能证明什么 |
| --- | --- |
| 根 SKILL.md 元数据有效、完整源码存在、发布清单通过 | 安装包／文件已准备 |
| 豆包正式导入完成，条目可见且检测通过 | 豆包技能列表安装完成 |
| `comsol_doctor`、工具发现成功 | MCP 已连接 |
| 案例 job 完成且校验通过 | 本次仿真完成 |

这些状态不能互相替代。没有工具返回或用户确认，就保留尚未完成的状态。
