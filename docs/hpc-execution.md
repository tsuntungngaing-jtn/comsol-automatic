# HPC 执行交接与恢复

仅在用户需要远程计算时读取。本文是适配契约，**本 Skill 没有因此实现 HPC 连接器或 submit_job 工具**。MCP 托管地址与计算位置分别记录；本地 MCP 也可连接学校集群，Hugging Face 不是必需层。

## 接入能力记录

在工作区保存 `execution/capabilities.json` 或等价记录：

| 字段 | 必须核实的内容 |
| --- | --- |
| `transport`, `tool_mapping` | 当前实际可调用的 MCP 工具及输入/输出 schema；提交、查询、传输、取回能力分别确认 |
| `scheduler`, `cluster`, `partition`, `account` | 集群真实配置，不假设 Slurm；仅保存非敏感配置 |
| `remote_workdir`, `transfer_mapping` | 本地与远端输入/输出路径、传输方式及可写范围 |
| `solver`, `solver_version`, `modules`, `license_status` | 实际版本、可用模块、批处理/分布式许可检查结果 |
| `resources`, `authorization` | 节点、进程、每进程线程、内存（每节点或总量）、墙钟、总预算、用户已授权范围 |
| `checked_at`, `limitations` | 检查时间、缺失工具或未验证能力 |

不要要求用户把 SSH 密钥、Token 或密码贴入聊天/清单。已有授权沿用，不为每次轮询重复询问；缺少必要配置时集中索取。编写指引或准备输入不等于已获无限计算额度。

无适配器时交付规格、需要的能力与接入阻塞项，状态 `blocked`。若先前已发生不确定提交，则保持 `submission_unknown`，不能改成“肯定没提交”。不猜工具名称，不通过外部终端/MPh/Java 或界面绕过本 Skill 的 MCP-only 约束。

## 准备与提交

1. 绑定 [规格和运行清单](simulation-specification.md)；在独立 run 目录冻结输入并计算哈希。COMSOL 模型准备、保存及检查通过 MCP 完成。
2. 用实际 MCP 传输能力上传已核实文件，检查远端哈希与路径。不得将私人资料默认转存公开托管空间。
3. 根据学校提供的启动规范和当前版本文档生成批处理配置；先核实调度器、模块、许可和启动命令。本文不提供可盲跑的通用 COMSOL 多节点脚本。
4. 将调度器任务数、每任务线程和求解器并行模式对应起来；申请两个节点不证明求解器会用两个节点，也不能将多节点进程数直接当本机线程数。
5. 提交前持久化 `submission_key`（由 run_id 和输入身份构成）、资源请求、脚本哈希与时间。提交时如适配器支持幂等键/任务元数据，则带上该键；本地记录本身不提供调度器幂等保证。
6. 保存真实返回的 scheduler job_id 和原始状态，映射到 execution_state；job_id 只是已接收证据，不是求解完成。

## 超时与会话恢复

提交超时且无 job_id 时：`submission_unknown` → 恢复原工具连接 → 按 run_id/submission_key、用户、工作目录和提交时间查调度器队列及历史记录。无查询能力时停留未知并说明需要的连接/记录，不直接重提。

找到唯一匹配任务则绑定 job_id 并继续；找到多个候选则列出歧义，不能自动取消或任选一个。仅“队列里没有”不足以证明没接收，还需考虑已完成/历史保留和查询权限。确认未接受后，记录核查证据，才在现有授权范围内重试。重新实际执行使用新 run_id 并关联 parent_run_id。

已有 job_id 时继续查询原作业。保存调度器原始状态与标准化状态，区分排队、运行、失败、取消、超时和节点错误；不要把 MCP 超时当调度器失败。轮询采用工具支持的等待/退避，避免忙轮询；只有实际配置了后台机制才能承诺持续监控。

## 完成与取回

调度器 COMPLETED 仅允许记录 `completed`，继续核查：

- 调度器退出码、求解日志和 solver 结束状态，没有被忽略的子步骤错误。
- 必需产物非空且对应本 run 的输入/工况，目标数据可解析且有限。
- 传回后的哈希与远端一致；保留 stdout/stderr 和求解日志。
- MPH 通过 MCP 在独立模型中载入，核对解/数据集与目标量；参考 [保存后重开](research-workflow.md)。

完成产物身份和完整性检查后才记录 `artifacts_verified`；这仍不自动令科学 claims PASS，需 [逐项验收](claim-validation.md)。产物缺失/解身份未知时保留 completed 与检查失败/未知事实，不改写成已验证。

远端保存的 MPH 尚未载入本地 MCP 会话时，只给实际文件位置和待载入状态，不能编造本地端口/模型名。真正载入后才提示“文件 → COMSOL Multiphysics Server → 从服务器导入 App”，使用 MCP 返回的名称。
